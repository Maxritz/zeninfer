# ZI-012 evidence: Q4_1, Q5_1 and BF16 scalar decoders

Date: 2026-10-31

## Scope

Implemented three additional GGML numeric decoders:

- Q4_1: 32 values per 20-byte block, fp16 scale and minimum followed by 16 packed nibble bytes.
- Q5_1: 32 values per 24-byte block, fp16 scale and minimum, 32 high bits and 16 packed nibble bytes.
- BF16: one little-endian bfloat16 value per 2 bytes.

`row_bytes()` and GEMV/GEMM block handling now recognise BF16 as an element-wise floating format. Q4_1/Q5_1 use their block sizes and alignment.

## RED

Added tests before implementation. Scalar CTest failed in `zen_core_tests` on the three `implemented` assertions and decoder/row-size expectations for Q4_1, Q5_1 and BF16. The other seven CTest cases passed.

## GREEN

Commands:

```sh
cmake -S . -B build-scalar -DZEN_BUILD_AVX2=OFF -DZEN_BUILD_TESTS=ON -DZEN_BUILD_BENCH=ON -DZEN_BUILD_SERVER=ON
cmake --build build-scalar -j2
(cd build-scalar && ctest --output-on-failure)
cmake -S . -B build-avx2 -DZEN_BUILD_AVX2=ON -DZEN_BUILD_TESTS=ON -DZEN_BUILD_BENCH=ON -DZEN_BUILD_SERVER=ON
cmake --build build-avx2 -j2
(cd build-avx2 && ctest --output-on-failure)
```

Results:

- Scalar: 8/8 CTest passed.
- AVX2: 8/8 CTest passed.
- Q4_1 and Q5_1 constant-block decode tests passed.
- BF16 normal, negative, subnormal and infinity decode tests passed.
- BF16 row byte count for four elements is 8.

## Limitations

This closes only three decoder formats within ZI-012. It does not close the remaining K-quants, IQ formats, MXFP4, GGUF end-to-end type-size coverage, independent reference corpus or fused kernels. Tests currently use deterministic hand-built blocks, not a third-party quantisation corpus. Windows/MSVC has not been run.
